# Changelog

All notable changes to OpenAgentix are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Fixed
- Agent Kourier lost its API server access, and crash-looped until the installer was run again, when the kind node's address changed after a Docker restart (`172.18.0.2` to `172.18.0.3`): its NetworkPolicy allowed the address found at install time as a `/32`. `components/channels/kourier.sh` now allows, on kind (every node's `spec.providerID` starts with `kind://`), the `/24` of the API server's node address, and keeps the exact endpoint addresses (`/32`) on every other cluster. `KOURIER_APISERVER_CIDRS` (comma or space separated CIDRs) overrides the detection. The next `./install.sh` run migrates an existing release. The derivation is in `components/channels/apiserver-cidrs.sh`; not yet run through a real Docker restart.

### Changed
- Knowledge graph, after the first real-model run (26 jobs, 42 359 tokens, 71 entities, 53 relations; extraction worked, the canary failed on retrieval: no path `Orion` to `Mira Okafor`, no chain to `Orion` for the canary question; the extraction HTTP 400 was fixed earlier by sending a strict JSON schema and no sampling parameters). **Entity resolution:** entities merge on the canonical name (category words such as team, cluster, service, region, system, api, group, squad, department, office dropped at either end), whatever the type, so `Team Basalt` = `Basalt`, `cluster Teal` = `Teal`, `Ink` service = `Ink` system; the displayed name is the more specific form and the others are aliases; distinct names (`Mira Okafor`/`Mira Lindqvist`, `Vane-2`/`Vane-3`, `Quill`/`Quire`) never merge; events without a digit in their name are scoped to their document. Known limits: English-only word list; two different things with one proper name in a collection merge. **Validation:** names that are only generic words, persons that are roles or have no proper name, and events without a date or identifier are dropped. **Prompt version `v2`** (default in the kb and the chart, was `v1`): naming rules for the model. **Changing the prompt version re-extracts a document on its next ingest.** **Migration 0005** (graph enabled only) adds `canon_name` and `other_types`, moves the unique key, and once clears extracted relations, mentions, entities and jobs (manual rows are kept), so collections must be re-ingested to rebuild the graph.
- `kb_graph_search`: returns maximal chains (a chain inside a longer one is dropped), ranked by distinct documents cited, then length, then seed score, then a stable tie-break, with a per-seed cap; one traversal per seed, longest paths first. Seeds: names in the question first; an embedding-only seed needs similarity 0.8, or 0.5 while fewer than three seeds exist. The real run's graph is now a test fixture. **The canary has not yet passed against a real model after these changes.**

### Added
- Curated knowledge-graph facts, no model involved ([ADR 0004](docs/decisions/0004-knowledge-graph.md), "Curated facts"; only with the graph on, routes absent otherwise): a **fact set** is a named, hand-written catalogue of entities and relations of one collection. kb admin routes `PUT/GET/DELETE /v1/collections/{collection}/graph/factsets/{id}` and `GET /v1/collections/{collection}/graph/factsets` (same admin token, body limit and no-content logging as the document routes): `PUT` replaces the fact set atomically and idempotently (the same body twice changes nothing and answers `changed: false`; facts that left the body are removed), at most 2000 entities and 5000 relations (413), every other mistake a 400 naming the item (`relations[7]: target is not an entity declared in this fact set`). Entity types, name length and predicate form as in extraction, but no grounding or generic-name rule; both ends of a relation must be declared in the same fact set. Stored with `origin = 'manual'`; a curated entity merges with an extracted one by canonical name and its name, type and description win; deleting or re-ingesting documents never removes it, deleting a fact set only un-marks entities that extracted facts still use. Migration 0006 (relations cite a document chunk or a fact set; tables `graph_factsets`, `graph_factset_entities`; existing rows kept; tested as an upgrade from the schema of migration 5).
- Graph tools show a curated fact as `Basalt -escalates_to-> Priya Venkat | curated: factset=org-catalogue source=... | "note"` (structured `curated`, `factset_id`), with no passage; a fact set counts as one source in ranking. `GET .../graph/stats` adds `manual` (curated entities, relations, fact sets).
- `hack/kb-graph-load.sh <collection> <factset-id> <file.yaml|json>` (YAML through `yq`; same transport and token handling as `hack/kb-ingest.sh`; `KB_GRAPH_LOAD_DRY_RUN=1`, `KB_GRAPH_LOAD_DELETE=1`). Sample `components/knowledge/graph-sample/org-catalogue.yaml` (fictional, none of the canary's answer chain) and, in its README, a question that needs one curated and two extracted facts. Unit and integration tested; **not yet run on the cluster**.
- `components/channels/tests/run.sh`: offline tests (fixtures, and `kourier.sh install` against a fake `kubectl` and `helm`) of the API server address derivation.
- Knowledge graph in the kb (`knowledge.kb.graph.enabled`, **off by default**: with it off the chart render, the schema and the tool list are unchanged; [ADR 0004](docs/decisions/0004-knowledge-graph.md)): entities and relations are extracted from ingested documents by a gateway model in a background worker (leased jobs, hourly token budget, strict grounded validation), stored as plain PostgreSQL tables and traversed with recursive SQL. Document text is sent to the extraction model. **Built and tested (unit, integration, local stand-in model); not yet run against a real model or on the cluster.**
- kb MCP tools `kb_graph_search`, `kb_graph_entity`, `kb_graph_paths` (read-only, registered only with the graph on): chains of facts up to three hops, every edge with `document_id`, chunk, source URI and quoted evidence, bounded in paths, passages and size, with the untrusted-content notice. Store traversal caps the edges followed out of one entity (`FanOut`, default 25, maximum 100).
- kb admin route `GET /v1/collections/{collection}/graph/stats` and `GET /v1/graph/stats`: entity, relation and job counts and the last error code, no content (only with the graph on).
- Extraction has its own gateway virtual key, user id `kb-extract` (Secret `kb-extract-key`): `install.sh` creates it only with the graph on and only when absent, never prints it, and registers its hash; `uninstall.sh` removes it with `PURGE_SECRETS=1`. `install.sh` now reads one key per annotation set (`openagentix.io/gateway-user<suffix>`, `gateway-key-secret<suffix>`, optional `gateway-key-name<suffix>`) instead of one pair per Deployment; the kb Deployment's existing annotations are unchanged.
- Chart: graph tool names added to the agents' kb tool list and a graph paragraph added to the prompt of `knowledge: true` agents only with the graph on; render fails if `knowledge.kb.graph.extractModel` is not a `gateway.models` name (when the chart's gateway is used).
- `components/knowledge/graph-sample/` (26 fictional documents and the canary question), `components/knowledge/graph-demo-values.yaml`, and `hack/kb-graph-canary.sh` (ingests the sample into `graph-canary`, waits for extraction, prints stats, tokens and the vector baseline, prints PASS or FAIL for the graph chain).
- README "Knowledge graph".

NetworkPolicies: the controller's A2A port admits those pods (namespace and pod label), an egress policy lets them reach only CoreDNS and the controller. 91 new chart assertions (302 to 393), written first.

- Observability MVP (chart block `observability`, **off by default**: the default render is byte-identical to before; [ADR 0003](docs/decisions/0003-observability.md)): one switch wires the model gateway's tracing (`spec.frontend.tracing` in the existing single policy), an `MCPTelemetryConfig` and a metadata-only audit log on the vMCP, `PodMonitor`s for every scrape target (only when the `monitoring.coreos.com/v1` API exists) and a marker ConfigMap that `install.sh` uses to configure the kagent controller and agent runtimes (`spikes/kagent/kagent-helm.sh` takes `KAGENT_EXTRA_VALUES`) and Agent Kourier (OTLP env, scrape policy, egress) from the same values, in both directions and only when they differ.

### Changed
- ADR 0002 status: Accepted (schedules: option A implemented; result delivery: notify service implemented).

- Chart `networkPolicy` (default on): ingress NetworkPolicies for `mcp-tools` (backends from their own namespace and the ToolHive operator; the vMCP also from `atenet-egress` and the kagent controller) and for the kagent controller port 8083 (the bridge pod by label, the `kagent` namespace, `atenet-egress`; other ports untouched).
- Tool-layer identity: `mcp.virtual.incomingAuth.type: oidc` is now the default. The chart renders an `MCPOIDCConfig` for the Substrate IdP (explicit JWKS URL, CA from a ConfigMap) and the RemoteMCPServer requests an actor JWT (`actorJwt`, audience `openagentix-vmcp`). `install.sh` copies the Substrate service CA from its ClusterTrustBundle into that ConfigMap.

### Fixed
- Telegram bridge: privacy fix for long-term memory. Every A2A request now carries `X-User-Id: telegram:<chat id>` (env `A2A_USER_ID_PREFIX`, chart `bridge.userIdPrefix`), so kagent no longer puts all Telegram chats into one shared memory space; a group chat is one identity. Tests: `TestSend_UserIDHeaderFromContext`, `TestBridge_UserIDIsPerChat`, `TestBridge_UserIDPrefixIsConfigurable`, `TestBridge_UserIDNeverDerivedFromMessageText`, `TestLoad_UserIDPrefix*`. Verified live: a fact saved under one id was recalled for it in a new conversation and not for another id.
- `install.sh` now rolls the bridge pod when `bridges/telegram` changes (pod annotation `openagentix.io/source-hash`, chart value `bridge.sourceHash`), as it already did for the kb.
- `services/kb`: an MCP tool call no longer outlives `KB_REQUEST_TIMEOUT`. The MCP SDK does not pass the HTTP request deadline to tool handlers, so with a stalled PostgreSQL a call hung until the client gave up (observed: 100 s client timeout hit); each tool call now runs under the request timeout and a timeout is reported as a tool error. Test: `TestMCPToolCallHonoursRequestDeadline`.

### Changed
- README Memory section: the "all Telegram chats share one memory space" caveat is gone (fixed, see above).
- The vMCP no longer accepts anonymous callers by default (HTTP 401 without a valid actor JWT). Set `mcp.virtual.incomingAuth.type=anonymous` for the old behaviour. The RemoteMCPServer reports `DiscoveryDisabled` because tools are listed at run time inside the agent.
- `components/tools/NOTES.md`: corrected the claim that RemoteMCPServer has no `headersFrom` or `tokenPassthrough`.

### Tried, not adopted
- kagent `config.server.auth.serviceAccount.authority: kubernetes` for the A2A endpoint: with `mode: insecure` the controller still answered requests with no token or a garbage token (200), so it adds no protection. Reverted; the bridge keeps the NetworkPolicy as its only control (`A2A_TOKEN_FILE` was not added).

## [0.1.0] - 2026-11-22

### Added
- `charts/openagentix` (chart 0.1.0, appVersion 0.1.0): first-party Helm chart, values-driven, one `enabled` flag per block.
  - Telegram bridge Deployment with `existingSecret` references and an optional chat-id allowlist; the chart renders no Secret.
  - Model gateway: Gateway, AgentgatewayModels from `gateway.models` (provider, upstream model rewrite, health, failover), and a single AgentgatewayPolicy for virtual-key auth, per-key token budget, retry and per-key log/metric attribution.
  - MCP tool layer: MCPGroup, MCPServers from `mcp.servers`, VirtualMCPServer with a `codeMode` toggle.
  - kagent wiring: RemoteMCPServer for the vMCP, and for each entry in `agents` a Harness, AgentTemplate, Agent and a ModelConfig bound to that agent's own virtual key. Skills must be digest-pinned OCI references.
- `charts/openagentix/tests/run.sh`: 84 shell assertions over `helm template` output.
- `install.sh`: one-command idempotent install (kind cluster, pinned upstream prerequisites, Secrets from environment, per-agent gateway virtual keys, bridge image and example skill build, adoption of hand-applied objects, `helm upgrade --install`).
- `uninstall.sh`: removes only the `openagentix` release; `PURGE_SECRETS=1` also removes the Secrets it created.
- Component scripts gained opt-in switches used by the installer: `PREREQS_ONLY=1` (`components/model-gateway/install.sh`, `components/tools/install.sh`) and `SKIP_FIRST_AGENT=1` with an optional `GOOGLE_API_KEY` and OS/arch detection for `kubectl-ate` (`spikes/kagent/up.sh`).
- Spike results kept as reference: kagent + Agent Substrate on kind (`spikes/kagent`), agentgateway model gateway (`components/model-gateway`), ToolHive MCP layer with code mode and OCI skills (`components/tools`), Google AX evaluation (`spikes/ax`).
- Telegram to A2A bridge in Go (`bridges/telegram`).
- Demo `assistant` agent: Claude Haiku through the gateway, ToolHive tools (fetch, OSV) and the `openagentix-canary` skill.
- `README.md` with architecture, quickstart, how to add an agent, and known limitations.
- `docs/decisions/0001-agent-runtime-kagent-vs-ax.md`: decision record for kagent as the agent runtime, with the same agent built and measured on Google AX (`spikes/ax/compare/RESULTS.md`).
- `bridges/ax-adapter` (experimental, not installed): A2A front for Google AX that runs one AX Task per turn, used for the runtime comparison.

### Changed
- Default gateway token budget raised from 100000 to 1000000 tokens per hour per virtual key (one tool question costs about 27k tokens). The chart now renders the number as an integer (`| int64`) so large values do not turn into floats.
- The chart's default skill reference is an unpullable placeholder (`registry.invalid`, zero digest) instead of a hard-coded node IP; `install.sh` sets the real reference.
- `hack/kind-config.yaml` replaces `spikes/kagent/kind-config.yaml`.

### Fixed
- `install.sh` now runs the component scripts through `bash`, so a missing execute bit no longer aborts the first install ("Permission denied").
- The skill registry is a dedicated `openagentix-registry` container on the `kind` docker network. It no longer shares the node's network namespace (which broke after cluster recreation and left a stale container named `ax-registry` looking healthy), and its address is looked up on every run.
- `spikes/kagent/up.sh` downloads `kubectl-ate` with curl and verifies its SHA-256; no `gh` login is required.
- The missing-allowlist warning in `install.sh` and the README now match the bridge, which refuses to start without `TELEGRAM_ALLOWED_CHAT_IDS`.

### Known issues
- Cold install verified twice from a deleted cluster on one machine with a warm Docker image cache. See "Known limitations" in `README.md`.
